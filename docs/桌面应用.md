# muz-ms-agent 桌面应用

桌面版使用 Electron 承载现有 Nuxt 界面。安装包内包含 Chromium、Node.js 和编译后的 Nitro 服务，用户打开应用即可练习，无需安装 Node.js 或手动运行服务。

## 启动与数据

主进程启动受限窗口，并通过 Electron `utilityProcess.fork` 启动内置 Node 服务。Nitro 仅绑定 `127.0.0.1`，使用 `NITRO_PORT=0` 由系统分配空闲端口。主进程等待服务监听并成功读取题库后显示应用。启动失败会显示原生错误对话框，提供重新启动或退出。

关闭窗口会退出应用并停止本地服务。再次双击应用会聚焦已有窗口，避免多个进程同时写入练习文件。参考链接在系统默认浏览器打开。

会话、报告和模型设置保存至 Electron `userData` 目录内的 `data/store.json`：

| 系统 | 默认目录 |
| --- | --- |
| macOS | `~/Library/Application Support/muz-ms-agent/data/` |
| Windows | `%APPDATA%\muz-ms-agent\data\` |

目录与 Web 开发时的 `.data/` 独立。更新安装包不会覆盖此目录；Windows 卸载默认保留练习数据。当前服务将模型密钥作为设置保存在本机数据文件中，不应将此目录公开或提交 Git。启动日志写入 Electron 日志目录的 `desktop.log`，每次启动覆盖；启动失败对话框显示其准确路径。

## 本地开发和打包

开发机器需要项目声明的 Node.js 版本及 npm。终端在项目目录运行：

```sh
npm ci
npm run desktop:dev
```

该命令先构建完整应用，再打开 Electron，验证的是与安装包一致的本地服务流程。界面修改后重新运行此命令。

```sh
# 生成当前系统的未安装应用目录，便于本机检查
npm run desktop:pack

# 生成当前系统安装包，不发布到外网
npm run desktop:build

# 在相应 macOS 构建机器上选择架构
npm run desktop:build -- --mac --arm64
npm run desktop:build -- --mac --x64

# 在 Windows 构建机器生成 Windows x64 安装程序
npm run desktop:build -- --win --x64
```

`scripts/desktop-prepare.mjs` 将桌面入口和精简的包信息放入 `.desktop-app/`。桌面入口仅使用 Electron 和 Node 内置模块，清单中的 `dependencies` 为空；`beforeBuild` 返回 `false`，明确告诉 electron-builder 依赖已由项目处理，跳过向父项目回溯收集依赖。完整 Nitro 运行依赖位于独立的 `.output/`，通过 `extraResources` 打包。产物位于 `dist-desktop/release/`：macOS 为 `.app`、`.dmg` 和 `.zip`；Windows 为 NSIS `.exe`。不要分发 `.data/`、环境变量文件或已有个人资料。

## Windows / macOS 构建工作流

`.github/workflows/desktop-build.yml` 提供手动触发和 `desktop-v*` 标签触发，在原生系统分别构建 macOS Apple Silicon、macOS Intel 和 Windows x64。工作流只上传 GitHub Actions 构建附件，不创建 Release，不发布应用。

运行工作流后，可以从 GitHub Actions 页面下载对应安装包。提供工作流不表示已在 Windows 运行或验证安装；应在目标系统完成安装、启动、一次面试、导出与重启数据保留检查。

已在 macOS Apple Silicon 上交叉生成 Windows x64 NSIS `.exe`，并检查安装器文件头、精简 ASAR 及内置服务文件。此项验证覆盖打包链条；尚未在 Windows 实机安装或启动。也可以在当前 macOS 构建机使用上面的 `--win --x64` 命令，无需先安装 Wine。

## 签名与窗口权限

当前配置显式关闭自动签名与发布，生成的是未签名、未经 Apple 公证的测试安装包。macOS Gatekeeper 和 Windows SmartScreen 可能提示无法验证开发者；仅应在确认来源的前提下通过系统提供的打开方式测试。分发给更多用户前需要开发者证书、签名和 macOS 公证，相关凭证不进入仓库。

渲染窗口关闭 Node.js 集成，启用 `contextIsolation`、`sandbox` 和 `webSecurity`，没有暴露原生 IPC 接口。外部导航和新窗口默认被阻止，仅合法 HTTPS 参考链接可交由系统浏览器打开。原生权限默认拒绝。主进程自动向应用同源请求加入每次启动随机生成的令牌，服务端校验令牌后才允许访问本地 API。

桌面应用仍以现有文字面试为主；没有增加语音、系统级录屏或自动更新。真实模型模式仍需要用户在应用设置中配置可用模型服务。
