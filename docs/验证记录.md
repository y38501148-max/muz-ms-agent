### 评分修复

完整报告改为逐题请求。每次只发送当前题的实际评分标准和问答，使用短 ID 标记回答，并为候选人原文划分编号片段。模型选择片段编号，程序还原原文和会话 ID，再校验知识点及独立／辅助作答范围。允许的片段和知识点编号写入每次请求的 Schema，模型不能用改写后的句子代替原话。各题结果由程序合并，不再让模型一次生成整场报告。

三种协议同时携带原生结构化参数和明确的任务输出约定。这样，兼容网关没有完整转发 Schema 参数时，模型仍能从请求正文读到字段要求。语法或字段格式失败可以做一次同模型纠正；拒绝、截断、连接错误和无效证据仍会报错，不用默认分数替代。

动态追问中，同一知识点可能返回多条标准。应用保留全部标准并合并到该知识点，未知知识点和来源仍会被拒绝。逐答判断只读取当前题问答，并单独提供本次回答原文，减少跨题记录对模型的干扰。

### 实际调用

已使用合成 PDF 简历跑通完整流程：导入解析、检查首轮简历注入、生成新题、识别错误解释、生成针对性追问、提交修正回答、生成完整报告。本轮报告包含 5 条原话证据，评分耗时约 29 秒；正确性评分为独立作答 0/4、辅助后 4/4。重复读取复用了已保存报告，没有额外调用模型。

接口适配测试覆盖 Anthropic Messages、OpenAI Responses 和 Chat Completions。实际延迟取决于模型服务，单次通过不作为延迟或评分准确性的承诺。

