# muz-ms-agent

Windows / macOS 面试练习应用。根据题库知识点生成本场问题，理解回答、判断正误并继续追问。

## 桌面版

使用 Electron + Nuxt 4 + Vue 3 + TypeScript + Ant Design Vue。安装包包含运行环境，打开应用后自动启动内置服务，无需用户安装 Node.js 或手动启动网页服务。

开发与打包需要 Node.js `^22.22.3`、`^24.15.0` 或 `>=26`：

```sh
git clone https://github.com/y38501148-max/muz-ms-agent.git
cd muz-ms-agent
npm ci
npm run desktop:dev
```

可从 [Releases](https://github.com/y38501148-max/muz-ms-agent/releases) 下载测试安装包，或自行构建：

```sh
npm run desktop:build
```

产物在 `dist-desktop/release/`。macOS 生成 `.app`、`.dmg` 与 `.zip`，Windows 生成 NSIS `.exe`。仓库包含在原生平台构建 macOS Apple Silicon、macOS Intel 与 Windows x64 的 GitHub Actions 工作流，执行方法、数据目录与签名状态见[桌面应用说明](docs/桌面应用.md)。安装包为未签名的测试版本。

保留浏览器开发入口：`npm run dev` 使用 [127.0.0.1:3100](http://127.0.0.1:3100)；生产服务可通过 `npm run build` 和 `npm start` 启动。桌面版使用独立的随机本地端口及访问令牌。

## 面试流程

1. 选择方向、公司背景、知识范围与难度，可导入简历并补充项目经历和 JD。PDF、DOCX、TXT、Markdown 先在本机解析，用户可编辑预览；点击开始时将文本注入首轮上下文。
2. AI 根据知识卡创作本场题干、实际评分标准、参考答案和提示；服务端保存完整快照与来源锚点。进行中的界面只接收已展示的提问。
3. 每次回答后，AI 根据原话判断为正确、部分正确、有误或信息不足，并自行创作有必要的追问。
4. 辅导模式即时解释判断；模拟模式保留判断到结束后展示。提示或反馈后的回答标为辅助作答。
5. 结束后生成逐答判断、证据评分、原始问答和后续练习，可导出 Markdown，或基于同主题知识重新出题。

模型输出须通过结构与引用检查：知识点 ID 和来源 ID 必须属于选定知识卡，引用由模型选择原文片段编号，程序还原对应文本和回答 ID，并检查所属题目与辅助标记。生成问题与追问不能复用已经展示的相同题干。此类检查能约束生成范围，不能替代知识正确性的人工审阅。

## 内容与模式

- 6 个方向：后端、前端、全栈、平台与基础设施、C / C++、AI 应用与 Agent。
- 36 张原创知识题卡，覆盖 12 类考点；每卡含三档固定示例、要点、参考答案与阅读资料，用于支持 AI 出题和自学。
- 简单、中等、困难三档。动态追问上限分别为 1、2、4 次，模型可提前换题。
- 通用岗位、两个明确标注的虚构场景，以及用户填写的公司与 JD。
- 回答、跳过、提示、切换辅导、暂停及刷新恢复、记录删除。
- 从 7 篇公开第一人称面经提炼 9 条提问策略，按岗位和知识范围用于出题、追问；可在「题库与知识点 → 面经提问策略」查看来源。

| 模式 | 出题与判断 |
| --- | --- |
| AI 自主出题 | 根据知识点创作题目和追问，逐答判断，面后独立读取原始问答评分 |
| 固定题卡练习 | 使用预设题干和追问，无需模型；只保留问答与参考要点，不判断正误或生成能力分数 |

旧版固定题卡会话仍按原流程恢复；新 AI 场次使用动态出题。题库页面显示的是知识题卡示例，本场生成题目和答案在结束后的复盘中查看。

## 模型配置

交付时 Base URL、模型、API Key 均为空。进入「模型设置」，填写服务支持的协议、包含 `/v1` 的地址、模型 ID 和 API Key，保存并测试。

支持 Anthropic Messages、OpenAI Chat Completions 与 OpenAI Responses。模型需支持 JSON Schema 结构化输出。服务端聚合流式可见文本，收到完成事件后校验，不展示思考内容。请求同时携带协议原生 Schema 和任务输出约定，适配未完整转发结构化参数的网关。为兼容部分网关，接受一个完整 JSON 围栏；语法或字段格式失败最多进行一次同模型纠正。HTTP、连接、拒绝和截断错误由用户手动重试，不自动更换模型。失败不提交本轮回答，界面保留输入。

也可使用显式环境配置：

```dotenv
MUZ_AI_BASE_URL=你的服务地址（包含/v1）
MUZ_AI_PROTOCOL=responses
MUZ_AI_MODEL=你的模型ID
MUZ_AI_API_KEY=你的密钥
```

`MUZ_AI_PROTOCOL` 可为 `responses`、`chat-completions` 或 `anthropic`。保存的应用设置优先，不自动继承其他应用或通用 `OPENAI_*` 变量的凭证。

AI 模式会把所选知识卡、岗位背景和问答发送给用户配置的模型服务，调用可能产生费用。密钥保存在本机服务端数据文件，API 只返回是否已配置；数据目录创建权限为 0700，文件为 0600。

## 数据与评分

桌面数据在 Electron `userData/data/store.json`，与开发目录 `.data/` 独立。更新安装包保留用户数据。Web 开发默认使用 `.data/store.json`，可用 `MUZ_DATA_DIR` 指定位置。

简历原文件不落盘；经用户审阅的文本随本场会话保存。导入限 5 MB / 20,000 字；扫描件未做 OCR，可改用可复制文本的 PDF 或直接粘贴。配置页间切换保留当前窗口中的配置草稿，刷新前尚未开始的草稿不作为会话保存。

会话采用单进程串行事务与原子写入；版本检查拒绝重复提交。完整题目、动态追问标准与知识锚点保存在本场快照中，题库更新不改写旧场次。

面试结束后先展示逐答判断，再按题生成维度报告。每次评分只读取这一题的实际问答和标准，模型通过编号选择证据片段，最后由程序合并为完整报告；模型调用失败时保留问答与逐答反馈，可以重试。独立与辅助作答分别评价，维度为 0—4 分或未评估，不显示未经校准的百分制总分。逐答判断和面后评分均可能有误，应结合证据及资料复核。未作答题不进行能力评分；代码未执行，项目经历未做外部核实，也不推断录用概率。

当前采用文字回答，尚未接入语音、代码执行沙箱、自动公司资料采集或自动更新。

## 开发与验证

```sh
npm test
npm run typecheck
npm run build
```

配置模型环境变量后，`npm run test:live` 会用合成 PDF 简历运行出题、错答追问、辅助后作答和完整报告，并删除临时数据。该命令会调用模型并产生费用。
